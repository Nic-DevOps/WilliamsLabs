Network Monitoring Lab

Deploy Prometheus, SNMP Exporter and Grafana on a Debian monitoring VM in the NET-MGMT VLAN, and build a live dashboard of the HQ network's health.

Stack: Prometheus · SNMP Exporter · Grafana Host: Debian 13, 10.10.50.25 Status: Complete

Overview

This is the monitoring backbone the live status widget on this site is built on. A Debian 13 VM in the NET-MGMT VLAN runs Prometheus, the SNMP Exporter, and Grafana, polling every core switch, access switch and router in the HQ network over SNMPv2c.

Data flow

Cisco devices (SNMPv2c, community monitoring) → SNMP Exporter (port 9116) → Prometheus (port 9090) → Grafana (port 3000)

SNMP on network devices

conf t
snmp-server community <community-string> RO

Reachability is verified from the monitoring VM before continuing:

snmpwalk -v2c -c 'community-string' <device-ip> 1.3.6.1.2.1.1.5.0

Prometheus scrape configuration

The SNMP job scrapes six HQ targets through the if_mib module and a custom monitoring_v2 auth profile:

scrape_configs:
  - job_name: 'snmp'
    static_configs:
      - targets:
          - 10.10.50.2
          - 10.10.50.3
          - 10.10.50.10
          - 10.10.50.11
          - 10.10.50.12
          - 10.10.50.13
    metrics_path: /snmp
    params:
      module: [monitoring_v2]
    relabel_configs:
      - source_labels: [__address__]
        target_label: __param_target
      - source_labels: [__param_target]
        target_label: instance
      - target_label: __address__
        replacement: 127.0.0.1:9116

Grafana dashboard

The HQ Network dashboard covers device availability (up), interface operational status, inbound/outbound traffic (rate(ifHCInOctets[5m])), utilization, errors, discards, and CPU/memory via Cisco MIBs. Display names, units, thresholds and value mappings (e.g. 1/2 → Up/Down) are configured as Grafana field overrides.

Failure test

Shutting down HQ-Router01 in CML was correctly detected by Prometheus as an SNMP timeout, and the target flipped to down within one scrape interval.

Multi-Site Static Routing Lab

Connect the primary campus to additional branch locations using routed WAN links and static routing, while preserving the existing VLAN, Layer 3 switching, and HSRP infrastructure.

Sites: HQ, Site A, Site B Routing: Static, via simulated ISP Status: Complete

Overview

The campus network from Lab 05 becomes HQ in a three-site enterprise. Site A and Site B each get their own core/access switching and a WAN router, and all three sites connect through a simulated ISP router over routed point-to-point links, tied together with manually configured static routes.

Topology

Each site's core switch connects to its own WAN router over a dedicated /30, and each WAN router connects to the central ISP-Router01 over another /30. Static routes on each internal router point remote-site subnets across the ISP.

Verification

Traceroutes confirmed correct path selection end to end — HQ User PC to Site A Research PC, and Site A Guest PC to Site B Server — with the ISP hop visible in each path.

Trade-offs

Static routes are predictable and easy to reason about, but every remote network has to be manually maintained on every router. That doesn't scale — which is exactly the problem OSPF solves in Lab 08.

What's next

Lab 07 layers SNMP-based monitoring over this multi-site network before Lab 08 replaces the static routes with OSPF.

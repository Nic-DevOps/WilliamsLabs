VLAN Trunking Lab

Introduce logical network segmentation with VLANs and extend those VLANs across switch-to-switch trunk links, while preserving the redundant switching infrastructure.

VLANs: 4 department VLANs + native Trunking: 802.1Q Status: Complete

Overview

VLANs logically divide the switching fabric into independent broadcast domains — without them, every port sits in VLAN 1 and broadcast traffic (like ARP) floods the entire network. This lab creates four department VLANs and extends them across two core and four access switches over 802.1Q trunks.

VLAN design

VLANNamePurpose
10SALESSales department users
20ENGINEERINGEngineering department users
30HRHuman Resources users
40MANAGERManager and executive users

No default gateways are configured in this lab — that's Layer 3, introduced in Lab 04.

Configuration order

  • Enable Rapid PVST+ (spanning-tree mode rapid-pvst)
  • Create VLANs 10/20/30/40 on each switch
  • Configure switch-to-switch links as 802.1Q trunks
  • Bundle trunk links into LACP EtherChannels
  • Assign access ports to VLANs
  • Set CORE1 as STP root primary, CORE2 as secondary
  • Enable PortFast + BPDU Guard on access ports
interface range fa0/1-8
 switchport mode access
 spanning-tree portfast
 spanning-tree bpduguard enable

Verification

PCs in the same VLAN could reach each other even when connected to different access switches — confirming VLANs propagate correctly across trunks. PCs in different VLANs could not reach each other at all, confirming Layer 2 isolation is working as intended.

What's next

Lab 04 adds a router to provide controlled communication between these now-isolated VLANs.

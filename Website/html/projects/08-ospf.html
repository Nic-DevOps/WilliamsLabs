OSPF Dynamic Routing Lab

Replace static routing with OSPF across the multi-site network, establish neighbor relationships, and verify automatic route convergence after a link failure.

Area: Area 0 (single-area) Process: OSPF process 1, all routers Status: Complete

Overview

Same three-site topology as Lab 06, but the manually maintained static routes are removed from every internal device and replaced with single-area OSPF, using loopback-based router IDs for stable, predictable adjacencies.

Router ID / loopback scheme

RangeAssigned to
10.255.0.xISP / hub devices
10.255.1.xHQ routers & core switches
10.255.2.xSite A routers & core switches
10.255.3.xSite B routers & core switches

Configuration

interface Loopback0
 ip address 10.255.1.1 255.255.255.255

router ospf 1
 router-id 10.255.1.1
 passive-interface default
 no passive-interface <WAN-interface>
 network 10.10.0.0 0.0.255.255 area 0
 network 10.0.100.0 0.0.0.3 area 0
 network 10.255.1.1 0.0.0.0 area 0

All interfaces are passive by default, with the WAN-facing interface explicitly opened so OSPF only forms neighbor relationships across router-to-router links — never toward end devices.

Verification

  • show ip ospf neighbor — neighbors reach FULL state
  • show ip route ospf — remote-site networks now show as OSPF-learned, not static
  • Inter-site pings confirmed connectivity without any manually configured routes

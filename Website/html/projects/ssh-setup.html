SSH Setup for Cisco IOS Switches

A guide to enabling SSH version 2 on a Cisco IOS or IOS-XE switch, so it can be managed remotely over its loopback with a local account instead of Telnet.

Platform: Cisco IOS / IOS-XE Time: About 10 minutes per switch Status: Complete

Purpose and scope

To enable SSH version 2 on a Cisco IOS or IOS-XE switch so it can be managed remotely. It applies to any new or reset switch (access, distribution or lab) that has no SSH yet, and covers local-user authentication.

Prerequisites

SSH will not come up without a crypto-capable image and a reachable management address, so these are checked first:

  • Console (or existing Telnet) access to the switch, with privileged EXEC (enable) rights
  • A crypto-capable IOS image (the k9 / universal image). show version should list K9 or crypto features.
  • A loopback address for SSH management (for example Loopback0 at 10.0.255.2/32) that the routing protocol advertises
  • A routed path from the admin PC's subnet to the switch loopbacks (for example via OSPF)
  • A hostname, domain name and admin username and password decided in advance
  • An SSH client on the admin PC (OpenSSH, PuTTY or Windows Terminal)

Procedure

The steps run in order from the console. The example values (CSW1, lab.local, 10.0.255.x) are replaced with each switch's own.

1. Enter configuration mode

enable
configure terminal

2. Set a hostname and domain name

RSA key generation fails while the hostname is still the default Switch.

hostname CSW1
ip domain-name lab.local

3. Create a local admin account

username cisco privilege 15 secret <strong-password>

4. Generate the RSA key pair

Use at least 2048 bits. If IOS asks whether to replace existing keys, answer no unless you mean to rotate them.

crypto key generate rsa modulus 2048

5. Force SSH version 2 and set session limits

ip ssh version 2
ip ssh time-out 60
ip ssh authentication-retries 3

6. Give the switch a loopback for management

The routing protocol has to advertise the loopback so the admin PC can reach it.

interface Loopback0
 ip address 10.0.255.2 255.255.255.255
exit

7. Lock the VTY lines to SSH with local login

This is done last so it cannot cut off an existing Telnet session partway through setup.

line vty 0 15
 login local
 transport input ssh
 exec-timeout 10 0
exit

8. Save the configuration

end
copy running-config startup-config

Stay on the console until the verification tests pass.

Verification

SSH is working when the switch reports version 2.0 enabled and a login from a separate device succeeds.

Then a real login is tested from a Linux machine, not the console. IOSv only offers older key exchange and host key algorithms, so the client has to allow them explicitly:

ssh cisco@10.0.255.2 -o KexAlgorithms=diffie-hellman-group14-sha1 -o HostKeyAlgorithms=ssh-rsa

A successful login lands at the CSW1# CLI.

Hardening

Once SSH works, these restrict who can reach it and stop secrets leaking. They are applied only after the verification tests pass.

  • Limit SSH to the management subnet with an ACL on the VTY lines: 
    ip access-list standard MGMT-SSH
 permit <management subnet> <wildcard mask>
 deny any log
line vty 0 15
 access-class MGMT-SSH in
  • Encrypt plain-text passwords still in the config, and add a legal banner: 
    service password-encryption
banner login #Authorized access only. Activity is logged.#
  • Slow down brute-force attempts by locking out repeated failures: 
    login block-for 120 attempts 5 within 60
login on-failure log
  • Remove unused local accounts and keep a single named admin per person where possible.
  • Back up the config after hardening with copy running-config startup-config, then archive a copy off the switch.

Rollback

If the change locks you out or breaks management access, revert from the console. Before starting, save the pre-change config with copy running-config flash:pre-ssh.cfg.

  1. If copy running-config startup-config has not been run yet, reload without saving: reload, answer no to saving, then confirm.
  2. If the config was already saved, restore the backup: configure replace flash:pre-ssh.cfg force (IOS-XE), or copy flash:pre-ssh.cfg running-config.
  3. To remove SSH only, run: 
    configure terminal
 crypto key zeroize rsa
 no ip ssh version 2
 line vty 0 15
  transport input telnet ssh
end
copy running-config startup-config
  4. Re-run show ip ssh and confirm the state matches what you intended.

Zeroizing RSA keys deletes them permanently; they must be regenerated to bring SSH back.
